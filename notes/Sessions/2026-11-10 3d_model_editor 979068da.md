# How spec-driven development applies to this project

**Asked:** "Share with me how spec driven development works and how it can apply to this project?" (2026-11-10)

## Done
- Analyzed repo structure and found spec-driven approach already in place
- Explained three-part pattern: contracts (shapes), data specs (per-thing files), validation (failure checks)
- Benefits: parallel work without constant meetings; design decisions recorded
- Costs: second place to be wrong; tendency to polish spec over exposing output to people
- Confirmed `docs/CONTRACT.md` is source of truth: units (metres, +X bow, +Z up), naming (`Group__Part` for Unreal compatibility), articulation format, nine simulator sockets
- Five modules meet at these contract boundaries only
- Identified risk: spec layer grows faster than the customer-facing output
