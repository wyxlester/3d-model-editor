# Articulation planned before the build, and the first Lincoln rebuild

**Asked:** plan, then build, how the editor's research and planning account for the joints VR-Forces needs
(Lincoln's weapons could only turn, never elevate), for every kind and not only ships. Explain "train" in the
research. Find out why a full Lincoln export had no weapons or Associated Components. Find out why the Build
viewport showed no model, and fix it. Keep the session notes updated before every commit.

## Done
- **Articulation roles** (here `c358e7b`, vrf-pipeline `73d126f`; CONTRACT §3b):
  - `catalog/articulation/roles.json` lists 17 moving parts: gun mount, naval gun, trainable and vertical
    launchers, radar, director, rudder, periscope/mast, crane, davit, deck elevator, hatch, landing gear, control
    surface, rotor, propeller and wheel.
  - Each role gives its chain of joints (motion, axis, limits, pivot, rest pose, what geometry hangs under it).
    E.g. a gun mount turns and its Gun joint elevates; a RAM launcher turns, elevates, and has a fixed launch
    point.
  - Roles are tagged with model kinds; a project kind maps onto them (`ship` → surface ship), so aircraft and
    vehicles need data, not code.
  - Research names each moving part's role and count. The design plan lists every instance, and cannot be saved
    or approved if an essential one (P0/P1) is missing.
  - Blender builds each one with the new helper `me3d.add_chain`. After every build the server checks the joints
    against the plan and the build AI fixes what is missing in the same turn. Exports are never blocked.
  - A test checks the roles against the VR-Forces install: each weapon chain binds its stock weapon whole, with
    matching limits.
  - End to end, a test ship built this way (Phalanx + RAM) exported with both weapons fully bound, no sim-only
    part, and MAK's own reader loading all 7 parts. That run found a new rule, now checked: every joint needs
    geometry under it, even a fixed one.
- **"Train"** is the naval word for turning a mount left and right; "elevate" is the barrel pitching. "Train and
  elevate" = two joints. The role, not the wording of the motion, decides the joints.
- **Lincoln export without weapons, investigated:**
  - The backend on port 8787 had run since 14 Nov 8:14 pm, without auto-reload: before the part-code mapping,
    the systems work and the roles.
  - Its draft left the weapon mounts, rudders and elevators without part codes, and those blanks were saved.
  - The export runs current code, but saved settings win over new suggestions, so no weapon had a mount to bind
    to.
  - Today's code, on the same build, fits all six weapons.
  - A plan to stop this recurring was written up, then built (next item).
- **The weaponless export can't happen silently again** (here `605f7b9`, vrf-pipeline `0407601`; CONTRACT §9b,
  §10):
  - **Stale server:** the server notes its code when it starts. The health check reports when files have changed
    since, Home and Review > MAK say to restart the editor, and the export report gets a warning.
  - **Saved part codes follow the suggestions:** the settings now save each part's suggestion. A saved code equal
    to it takes today's suggestion, so new rules apply; a code changed by hand stays.
  - **Older settings:** rows that differ from today's suggestion are marked, with a "Use the current suggestions"
    button. The panel's systems list now picks codes exactly as the export does; before, it showed weapons the
    export then left out.
  - **The export warns:** about stale settings, about a coded gun under a static mount, and with "Weapons fitted:
    N of M weapon mounts". The panel counts warnings instead of saying "every check passed".
  - Re-run on the weaponless Lincoln package, the same export now gives 8 warnings.
- **Build viewport fixed** (here `623c8e8`):
  - Right after the plan's hull-only build, all 36 planned joints were "missing", and their warnings (12,000
    characters) squeezed the 3D view to zero height.
  - Now: one short warning per moving part, folded into one "N moving parts missing joints" line; the status bar
    is capped and scrolls.
- **Joint limits fixed:** limits were applied before the custom ops that make the joints, so limits on those
  joints, including the AI's own `set_joint_limits`, were silently ignored. They now apply after.

## Decisions
- Gate the plan, nudge the build: a plan with a missing essential joint can't be approved; a build with one only
  warns, and the AI fixes it.
- Roles are simulator-neutral and tagged by kind; MAK evidence is data, checked by a test against the install.
- A stale server gets a warning banner, not auto-reload, which would kill a build in progress (proposed, not
  built).
